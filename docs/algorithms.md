# Deformation algorithms and limits

This document separates the algorithms in the fast vertex stream from mesh-wide editing methods. A frame can apply corrective shape deltas, skin vertices, and update shading data in distinct passes. The topology and bind data stay fixed while positions and bone transforms change. The engine owns the input and output buffers and can schedule disjoint vertex ranges on its own workers.

## Linear blend skinning (LBS)

For rest position $p$, affine joint transforms $M_j$, and normalized nonnegative weights $w_j$,

$$p' = \sum_j w_j M_j(p,1), \qquad \sum_j w_j=1.$$

LBS accepts translations, rotations, nonuniform scale, and shear. Because the weighted matrix generally ceases to be rigid, joints can lose volume or form the familiar twisting/collapsing artifact. It is a useful baseline and the appropriate path when an arbitrary affine joint transform is required. Bone transforms should already include inverse bind transforms if the input positions are in bind space. A vertex with no influences needs an explicit identity rule; a zero-sum or invalid influence list must not silently produce the origin.

For an affine transform with linear block $A$, a geometric normal transforms by $(A^{-1})^T$ when $A$ is invertible. Applying this to the *blended* $A$ is only the local affine approximation: skin weights vary over the surface and morphs can change its geometry. A weighted blend of joint-transformed normals is another approximation. For final surface normals after substantial displacement, recompute from the deformed triangles. Singular transforms have no inverse transpose and require a documented fallback or geometry-based recomputation.

## Dual-quaternion skinning (DQS)

A unit dual quaternion $\hat q=q_r+\epsilon q_d$ represents one rigid rotation and translation. For each influenced vertex, choose consistent quaternion signs, form $\hat b=\sum_j w_j\hat q_j$, normalize its real part, and transform the position with the resulting rigid transform. Its translation is the vector part of $2b_d b_r^*/\|b_r\|^2$; the position and normal use the rotation represented by $b_r/\|b_r\|$. This follows the original [Kavan et al. dual-quaternion skinning paper](https://users.cs.utah.edu/~ladislav/kavan07skinning/kavan07skinning.pdf).

The signs matter because $\hat q$ and $-\hat q$ represent the same rigid transform but can cancel when blended. Align each nonzero influence's real quaternion hemisphere to a reference influence before accumulation. A nearly zero real-part norm is an invalid or ambiguous blend and needs an explicit failure/fallback. DQS better retains volume around many bends, but it does not represent scale or shear. It can take an undesirable short rotation path around 180 degrees; the [follow-up analysis](https://users.cs.utah.edu/~ladislav/kavan08geometric/kavan08geometric.pdf) discusses both this limitation and a separate two-phase treatment of nonrigid transforms. Do not pass a scaled matrix to a rigid DQS converter and expect its scale to survive.

## Corrective shapes

Sparse corrective shapes store a rest-space delta $\Delta p_i$ only for affected vertices. At a given pose, form $p_i^*=p_i+\sum_k a_k\Delta p_{ki}$, then skin $p_i^*$ if the shape is authored before skinning. Shapes authored in output/posed space must instead be applied after skinning; these are different operations and should be named explicitly by the caller. This design makes the cost proportional to the number of active sparse entries plus the number of skinned vertices. Corrective weights and delta units are artist-defined and should not be confused with normalized skin weights. [Pose-space deformation](https://doi.org/10.1145/344779.344862) motivates pose-driven corrections; a shape blend alone does not automatically infer a joint angle or an anatomically plausible correction.

## Shading and topology

For a triangle $(a,b,c)$ with deformed positions, its oriented area vector is $(p_b-p_a)\times(p_c-p_a)$. Summing these vectors by vertex and normalizing produces area-weighted *smooth vertex normals*. `NormalTopology` prepares vertex-to-face adjacency once; each frame computes one cross product per face, then gathers adjacent face vectors independently per vertex. It stores $O(F)$ face crosses, $O(F)$ adjacency indices, and $O(V)$ offsets, avoiding races and atomics in a parallel face or vertex pass. This is not the same as a face normal, a split corner normal at a hard edge, or a fully accurate differential of the continuously skinned surface. Degenerate faces contribute zero. Engines that need hard edges should duplicate vertices or use corner-domain normals with an explicit smoothing partition.

Tangent space also has UV and mirrored-island seams. A single tangent per geometric vertex cannot represent every corner. The [MikkTSpace reference interface](https://github.com/mmikk/MikkTSpace/blob/master/mikktspace.h) explicitly warns against averaging its per-corner results back into an existing index list. A position/normal update is not a MikkTSpace-compatible tangent reconstruction; run the engine's tangent pipeline on the required corner data when normal-mapped materials demand it.

## Dense mesh cost model

With $V$ vertices, $F$ triangles, and at most $K$ skin influences per vertex, LBS or DQS takes $O(VK)$ work and writes $O(V)$ positions. A sparse corrective pass takes $O(S)$ work for $S$ active delta entries if the base position stream is already copied or initialized; full output initialization adds $O(V)$. Area-weighted normal reconstruction takes $O(F+V)$ work and uses the prepared adjacency plus the per-frame face-cross array described above. These are operation counts, not a promise of a particular frame rate. Memory bandwidth, cache layout, compiler vectorization, workers, vertex format, and CPU all affect throughput. Prepare and validate static influences and indices once; allocate working buffers outside the frame loop. Parallel vertex ranges are independent for skinning, and the two normal passes split work by disjoint faces and disjoint vertices, respectively.

## Tetrahedral render embedding

`TetraEmbedding` attaches dense render points to a lower-resolution tetrahedral simulation mesh. During preparation, it validates tetra indices and nonzero volumes, builds a rest-space bounding-volume hierarchy, finds each render point's containing tetrahedron, and stores four barycentric weights. Runtime evaluation is a weighted sum of four *current* simulation positions per render point, $x'=\sum_{k=0}^{3} w_k x_k(t)$; it is $O(R)$ for $R$ render points, writes the caller's buffer, and has no per-frame allocation. The prepared mapping is tied to a particular rest pose and topology; rebuild it when either changes. Outside points can be rejected, projected to the nearest tetra boundary, or bound with signed barycentric extrapolation up to a finite distance. Projection changes their rest position; bounded extrapolation preserves that position under the identity pose but can amplify a distorted tetrahedron. This is a kinematic transfer of simulator motion to rendering, not a contact or elasticity model.

`TetraQuality` measures deformation independently of the chosen simulator. For each tetrahedron it reports current signed volume divided by reference signed volume, flags negative ratios as inverted, counts nearly collapsed ratios under a configurable threshold, and records minimum/maximum edge-length ratios. It visits six edges per tetrahedron, uses $O(T)$ work for $T$ tetrahedra, and does not allocate during evaluation. These diagnostics expose failure modes; they do not prevent inversion or establish calibrated material behavior.

## Optional tetrahedral XPBD solver

`SoftbodySolver` is a small, self-contained position-based dynamics option when an external physics engine is unavailable. It prepares unique tetra edges, signed rest volumes and outer boundary faces, then uses sequential Gauss-Seidel extended position-based dynamics (XPBD) edge-length and volume constraints over caller-selected substeps and iterations. Compliance appears as $\alpha/h^2$ for substep length $h$, so it controls softness across timestep changes. Zero inverse mass pins a vertex; gravity, velocity damping, and fixed targets are explicit. Its boundary-triangle/sphere projection supports kinematic spheres, but **does not apply reaction force to the sphere**, model friction, or resolve general self-collision. It cannot by itself validate two-way embedded rigid-body mechanics or material parameters. The XPBD formulation is described by [Macklin, Müller and Chentanez](https://doi.org/10.1145/2994258.2994272).

After preparation the solver reuses its working vectors and does not allocate per step. Its order of work is approximately $O(S[V+I(E+T+C B)])$ for $S$ substeps, $I$ iterations, $E$ unique edges, $T$ tetrahedra, $C$ kinematic spheres, and $B$ boundary faces. The boundary face check has a cheap AABB reject but no spatial acceleration structure. The solve is sequential within one body; independent solver instances can run on separate application workers. XPBD stiffness and visual stability depend on mesh resolution, mass, substeps, iterations, timestep and contact setup; report those settings with any throughput result.

## Mesh-wide editing: ARAP is a separate solver

As-rigid-as-possible (ARAP) surface editing minimizes local edge deviations under position constraints. The [Sorkine and Alexa paper](https://www.cs.jhu.edu/~misha/ReadingSeminar/Papers/Sorkine07.pdf) uses cotangent weights $w_{ij}=\tfrac12(\cot\alpha+\cot\beta)$ and alternates two steps: find a best-fit rotation $R_i$ for each vertex neighborhood, then solve an anchored sparse Laplacian system for positions. In its spokes formulation, the global right-hand side is $b_i=\tfrac12\sum_j w_{ij}(R_i+R_j)(p_i-p_j)$. The matrix depends on rest geometry and the fixed anchor set, so a prepared factorization or preconditioner can be reused when only handle positions change. Local rotations require a robust orthogonal fit with reflection correction, especially for near-degenerate neighborhoods. Disconnected components need sufficient constraints; unconstrained translation is a nullspace.

ARAP is a nonlinear iterative edit and its cost and convergence depend on topology, constraints, and solver. It should not be described as the fixed-cost real-time skinning path. An implementation needs a measurable residual, an iteration budget, and explicit behavior on failure or exhausted iterations. Cotangent weights reduce triangulation bias, but degenerate triangles and poorly conditioned constraints demand care. [libigl's ARAP documentation](https://github.com/libigl/libigl.github.io/blob/docs/docs/tutorial.md) describes its separate precomputation and solve phases and alternative energies. Unless an ARAP solver is explicitly exposed by the library, this section is design context, not an implemented feature claim.
